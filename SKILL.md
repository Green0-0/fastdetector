FastDetector is a pipeline for end-to-end development of AI text detectors, with enough flexibility to also filter and generate synthetic data for any domain!

## Package Setup
You should use ``uv`` when setting up FastDetector. When installing vLLM or Aphrodite to run LLMs, it must be in a seperate venv, ideally named ``.vllm`` or ``.aphrodite``. FastDetector is also compatible with general OAI endpoints. It goes without saying that the appropriate versions of torch/cuda should be installed to work with vLLM.

Additionally, an appropriate flash attention wheel should be installed for the qwen embedding models, see: https://github.com/mjun0812/flash-attention-prebuild-wheels/. 

## Codebase
The codebase is split into four distinct paths: prompting, pipelining (used for filtering and generation), statistics, and analysis. There are also generic scripts, such as src/fastdetector/utils.py primarily for managing hf datasets, src/fastdetector/frontend/toml_config.py and src/fastdetector/frontend/toml_loader.py for managing TOML configurations. Everything in the archives can be ignored; these scripts are depreciated and likely broken. Do NOT update the archive scripts, these will be deleted soon.

### Prompting
Example prompts are written in sample_prompts; these can just be basic json lists. However, these must be formatted to be a list of json dicts with:
```
{
    "chat_turns": A list of chat turns sent to the AI, where {{DOC}} references the document and {{RESP_N}} references a previous chat turn.,
    "use_multiturn": A boolean that when true, uses standard multiturn, but otherwise treats the latest message as a brand new message, with {{RESP_N}} markers used to fetch previous outputs.,
    "examples": A list of few-shot examples, where each example is a list with the first element being the human message and the second being the AI response.
    "metadata": Data used to ID the type of prompt this is.
}
```
See prompts/ for examples.

### Pipelining
Assuming the prompts are already parsed correctly, the pipe.py / engine_config.py / llm_utils.py / generator.py files in src/fastdetector/ will handle them with a pipeline config and generate the resulting dataset. Usages include gen.py (which generates AI responses) and filter.py (which processes human responses into continuous text sequences with no boilerplate), with their respective toml configurations. These scripts also include post-processing filters.

Importantly, everything including pipelining and afterwards supports dataset splitting/multi machine batching. This works by splitting a dataset into subsets, and having a seperate machine process each subset. The subset a machine processes is indexed by the batch-id that the entrypoints accept; this batch-id MUST not be duplicated (if you are batching). Alternatively, you can just pass batch-id 0 and remove the output shard config parameter for filter.py to work in the single-machine scenario.

### Statistics
Once you have a dataset of human-AI pairs, you can calculate a lot of statistics on them. These range from basic lexical distance metrics, to embedding metrics, editlens model edit scores, and even llm based metrics such as entropy or perplexity. The detailed code is specified in src/fastdetector/statistics, with some editlens code specified in src/fastdetector/modeling. Note that most functions are standardized to return distances instead of similarities, which may involve inverting the return value. There are three primary entry points with similarly named configuration files: stats/distance_stats.py which calculate embedding and lexical distances, llm_stats.py which calculates llm stats and llm-based classifier stats (such as binoculars), and editlens_stats.py which runs an editlens model.

### Analysis
None of the statistics scripts will generate a readme or results by themselves, you MUST run the analysis script, which uses the backend scripts in src/fastdetector/visualization. This script generates a comprehensive readme of all desired stats (configured in config/analysis.toml) and automatically builds graphs/charts and pushes to huggingface. A JSON spec of the results is also pushed, so it can be downloaded later and seperately analyzed locally (see compare_summary.py).

Note: Statistics and analysis should work on datasets that were not generated by the pipeline as well, but may require minor modifications to config files to ensure the datasets with different formats are processed together.
